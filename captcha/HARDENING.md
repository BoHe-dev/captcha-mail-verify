# 渗透测试与加固记录

> 上线前做了一轮完整的渗透测试：自己当攻击者，把注册验证的每条路径都打了一遍。
> 发现 1 个可绕过漏洞 + 一串功能缺陷，以下是发现、修复和复测结论，以及过程中沉淀的方法论。

## 一、测试发现

| # | 攻击路径 | 修复前结果 |
|---|---|---|
| 1 | 纯脚本（无行为数据）直接调 verify | score 0.2 → 落图片挑战，挡住 |
| 2 | **跳过 init/verify 直接刷挑战图** | **可绕过**：不带任何会话凭证就能拿图、提交点选拿令牌 ❌ |
| 3 | AI 视觉解图片点选 | 可解（自研/开源验证码的固有上限），配合 #2 等于全自动批量注册 ❌ |
| 4 | 令牌重放 | 已有 jti 烧毁防线 ✅ |
| 5 | 伪造/篡改令牌 | HMAC 验签 ✅ |

## 二、修复清单

| # | 修复 | 说明 |
|---|---|---|
| 1 | **ccid 挑战续接凭证** | verify 低分 → 签发一次性 ccid（2min TTL）；拉图/点选校验必须携带、成功即烧毁 → 堵死 #2 跳过路径 |
| 2 | 限流收紧 | 拉图 10/min、点选校验 8/min（IP 维度） |
| 3 | 令牌 TTL 5min→2min | 缩小令牌窗口（后按实际使用反馈放宽至默认 24h、可配：提前验证后慢慢填表不该让勾失效，jti 一次性烧毁已限制重放价值） |
| 4 | 取消 cid/ccid 严格 IP 绑定 | 移动 NAT 出口漂移 + 双栈 v4/v6 切换会误伤真人（实测复现"验证会话不一致"）；令牌安全不依赖 IP 绑定 |
| 5 | 直通线 0.5→0.7 | 行为评分器在交互事件不足时会按缺证扣分（宽松放行设计），稀疏合成点击此前 0.53~0.6 可直通；提线收紧。注意键盘/触摸事件也被评分，反复按回车反而可能"凑够判决"直通——见 #7 |
| 6 | 挑战面板显示 bug | `style.display=''` 会回退到样式表的 `display:none`，面板从未显示过；改 `'block'` |
| 7 | **挑战锁定** | 低分转挑战后复选框锁定（点击/回车/Tab 全部无效），点选通过自动勾选——堵死"反复触发 verify 用键盘事件凑判决直通"的绕过路径 |
| 8 | 点错自动换新图 | 图片挑战的 key 一次校验即作废，原图重试无意义 |
| 9 | 窄屏适配 | 挑战组件根元素实际占宽 = 传入宽 + 内边距×2 + 边框，按容器实宽 -26 分配才不裁切；标题栏可换行、提示条等比缩放；ResizeObserver 持续跟随容器 |
| 10 | 点选坐标换算 | 等比缩放显示后，点击坐标是"显示尺寸"空间的，服务端按"原图尺寸"校验——必须按比例还原再提交，否则缩放后怎么点都错 |
| 11 | 换图失效 | 组件"复用 vs 重建"双路径重构时 setData 被放进重建分支，复用路径跳过灌图 → 图片永不更新。教训：副作用放双路径共同出口 |
| 12 | 加载动画 | 弱网拉挑战图数秒期间面板空白像卡死；加转圈 + 旧图置灰 |

## 四、方法论（比修复本身更值钱）

1. **curl 测不出前端 bug**。面板显示、换图失效、坐标错位全是 UI 层问题，curl 一路绿灯。UI 改动必须用无头浏览器 + mock 服务端到端实测。
2. **第三方组件的"传入宽度"≠"实际占位宽度"**。go-captcha 根元素宽 = width + padding×2 + 边框，wrapper 样式必须读源码换算，否则裁切。
3. **显示尺寸 ≠ 校验坐标系**。等比缩放显示 + 服务端原图校验的组合，必须在提交前做坐标换算，容差救不了 26% 的比例偏差。
4. **双路径重构时副作用放共同出口**。"复用"和"重建"两条路都要执行的逻辑（如灌图）单独抽出来，否则必有一条丢状态。
5. **改静态资产必须 bump 引用版本号**。浏览器缓存 + CDN 会放大陈旧周期，漏 bump 的故障会一轮一轮反复出现。
6. **mock 要能区分对错**。测试换图就必须每次返回不同的图，测试坐标就必须真校验坐标——永远返回同一张图、永远返回成功的 mock 什么都测不出来。
7. **自研反代必须透传查询字符串**。`challenge?ccid=` 丢了参数是无报错失败，最隐蔽。
